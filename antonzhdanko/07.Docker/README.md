# 07. Docker

## Objective

The purpose of this homework is to learn basic Docker commands and build a
Docker image for a small web application.

The application is written in Python using Flask and is served by Gunicorn. It
provides two endpoints:

- `/` — returns a greeting, container hostname and environment name;
- `/health` — returns application health status.

## 1. Docker installation and basic commands

Docker Desktop is installed on macOS. The client and Compose versions were
checked with:

```bash
docker --version
docker compose version
```

Result:

```text
Docker version 29.4.2, build 055a478
Docker Compose version v5.1.3
```

The Docker Engine was checked with:

```bash
docker info --format '{{.ServerVersion}}|{{.OSType}}|{{.Architecture}}'
```

Result:

```text
29.4.2|linux|x86_64
```

Docker Desktop on macOS runs Linux containers inside a Linux virtual machine.

### Hello World container

```bash
docker run --rm hello-world
```

Result:

```text
Hello from Docker!
This message shows that your installation appears to be working correctly.
```

This command checks the complete basic flow: the Docker client contacts the
daemon, the daemon pulls the image from Docker Hub, creates a container and
starts its main process. `--rm` removes the stopped test container.

Useful commands for inspecting containers and images:

```bash
docker ps
docker ps -a
docker images
docker inspect hello-world
docker history hello-world
```

## 3. Dockerfile explanation

```dockerfile
FROM python:3.13-slim

ENV PYTHONDONTWRITEBYTECODE=1 \
    PYTHONUNBUFFERED=1

WORKDIR /app

COPY requirements.txt .
RUN pip install --no-cache-dir --requirement requirements.txt

RUN useradd --create-home --uid 10001 appuser

COPY --chown=appuser:appuser app.py .

USER appuser

EXPOSE 8080

CMD ["gunicorn", "--bind", "0.0.0.0:8080", "--workers", "2", "app:app"]
```

- `FROM` selects a small Python base image.
- `ENV` disables Python bytecode files and enables immediate log output.
- `WORKDIR` sets `/app` as the working directory.
- Dependencies are copied and installed before the application source so that
  Docker can reuse this layer when only `app.py` changes.
- `--no-cache-dir` prevents pip package cache from remaining in the image.
- `appuser` is an unprivileged runtime user with UID `10001`.
- `COPY --chown` gives the application files to that user.
- `EXPOSE` documents the application port inside the container.
- `CMD` starts Gunicorn as the main container process.

## 4. Building the image

The base image was downloaded and the application image was built:

```bash
docker pull python:3.13-slim
docker build --tag antonzhdanko/docker-homework:07 .
```

Check the resulting image:

```bash
docker images antonzhdanko/docker-homework:07
```

Result:

```text
REPOSITORY                     TAG   SIZE
antonzhdanko/docker-homework   07    183MB
```

The tag `07` identifies the homework version. A specific tag is preferable to
using only the mutable `latest` tag.

## 5. Running the container

```bash
docker run --detach \
  --name anton-docker-homework \
  --publish 8080:8080 \
  --env APP_ENV=course \
  antonzhdanko/docker-homework:07
```

- `--detach` runs the container in the background;
- `--name` assigns a readable container name;
- `--publish 8080:8080` maps host port 8080 to container port 8080;
- `--env` passes a runtime configuration value.

Check the running container:

```bash
docker ps --filter name=anton-docker-homework
```

Result:

```text
NAMES                   IMAGE                             STATUS   PORTS
anton-docker-homework   antonzhdanko/docker-homework:07   Up       0.0.0.0:8080->8080/tcp
```

## 6. Testing

Test the main endpoint:

```bash
curl --fail http://localhost:8080/
```

Result:

```json
{"environment":"course","hostname":"53bed524bfd1","message":"Hello from Anton's Docker container!"}
```

The hostname is generated by Docker for the running container and will change
when the container is recreated.

Test the health endpoint:

```bash
curl --fail http://localhost:8080/health
```

Result:

```json
{"status":"ok"}
```

Verify that the application does not run as root:

```bash
docker exec anton-docker-homework id
```

Result:

```text
uid=10001(appuser) gid=10001(appuser) groups=10001(appuser)
```

View application logs:

```bash
docker logs anton-docker-homework
```

The logs show Gunicorn listening on `0.0.0.0:8080` and starting two workers.

## 7. Cleanup

Stop and remove the container:

```bash
docker stop anton-docker-homework
docker rm anton-docker-homework
```

Alternatively, remove a running container with one command:

```bash
docker rm --force anton-docker-homework
```

Remove the application image if it is no longer needed:

```bash
docker image rm antonzhdanko/docker-homework:07
```

my own image from a Dockerfile, published a container port, tested the web
application and verified that its process runs as a non-root user.

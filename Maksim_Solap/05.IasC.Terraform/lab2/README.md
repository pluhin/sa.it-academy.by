# Homework Assignment 2: Variables, outputs and locals

## 🎯 Цель работы
Настроить валидацию входных данных, скрыть секреты из вывода терминала и изучить приоритеты передачи переменных.

## 📈 Приоритет передачи переменных (Precedence Order)
Если для одной и той же переменной заданы разные значения, OpenTofu выберет значение с наивысшим приоритетом. Порядок от **низшего к высшему**:

1. **Значения по умолчанию** (блок `default` внутри `variables.tf`).
2. **Переменные окружения** (например, `export TF_VAR_secret_token="value"`).
3. **Файлы конфигурации** (`terraform.tfvars`, `*.auto.tfvars`).
4. **Флаги командной строки** (например, `-var="secret_token=value"`).

## 🛡️ Валидация и чувствительные данные (Sensitive)
* **Валидация**: В переменной `filename_prefix` настроено ограничение на длину строки (не менее 3 символов). При попытке передать более короткое имя OpenTofu прерывает работу и выводит понятную ошибку.
* **Sensitive**: Переменная `secret_token` и зависящий от нее `output` помечены флагом `sensitive = true`. В логах выполнения `tofu apply` и при вызове `tofu output` вместо текста отображается `(sensitive value)`. Это предотвращает случайную утечку паролей в логи CI/CD систем.

## 🔄 Разбор Plan Diff: Обновление (In-place) vs Замена (Replacement)
При изменении переменной `pet_length` OpenTofu показывает в плане замену ресурса (значок `-/\+` или `destroy and then create replacement`).

* **Update in-place (Обновление на месте)** происходит, когда изменяемый параметр можно применить к существующему ресурсу (например, изменить текст внутри файла).
* **Replacement (Замена/Пересоздание)** происходит, если провайдер не поддерживает изменение параметра "на лету" (нельзя изменить длину уже сгенерированного слова `random_pet`). Ресурс уничтожается и создается заново с новым ID, что влечет за собой пересоздание всех зависимых ресурсов.

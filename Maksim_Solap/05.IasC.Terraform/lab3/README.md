# Homework Assignment 3: Modules

## 🎯 Цель работы
Вынести логику генерации конфигурационных файлов в изолированный переиспользуемый модуль и развернуть его для трех сред (`dev`, `stage`, `prod`) с помощью цикла.

## 🧩 Какие проблемы решают модули?

1. **Исключение дублирования кода (DRY - Don't Repeat Yourself)**: Вместо копирования блоков кода для каждого нового окружения, код пишется один раз в виде шаблона (модуля) и вызывается с разными параметрами.
2. **Логическая абстракция**: Модули позволяют скрыть сложную внутреннюю архитектуру ресурсов. Пользователю модуля достаточно передать простые входные переменные, не вникая в то, как именно устроена логика внутри.
3. **Упрощение поддержки и стандартизация**: Изменение, внесенное в код одного модуля, автоматически применяется ко всем окружениям, которые его используют. Это гарантирует одинаковые стандарты конфигурации во всей компании.

## ⏳ Когда стоит выделять код в модуль?
* Когда аналогичная группа ресурсов создается в проекте **более двух раз** (например, разные регионы, среды или клиенты).
* Когда размер одного файла конфигурации (`main.tf`) начинает превышать **500–1000 строк**, ухудшая читаемость кода. Разделение монолита на логические модули (сеть, базы данных, вычислительные узлы) упрощает навигацию.
* Когда необходимо создать стандартный шаблон инфраструктурного компонента для использования другими командами в организации.

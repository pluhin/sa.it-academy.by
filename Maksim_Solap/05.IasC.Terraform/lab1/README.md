# Homework Assignment 1: First configuration and state

## 🎯 Цель работы
Изучить базовый жизненный цикл инфраструктурного кода в OpenTofu, познакомиться с локальными провайдерами и понять принципы работы файла состояния (`state`).

## 🛠️ Что делают основные команды OpenTofu

* **`tofu init`** — Инициализирует рабочую директорию. Скачивает указанные в `versions.tf` провайдеры (`local` и `random`) из реестра `registry.opentofu.org` во внутреннюю папку `.terraform/` и создает lock-файл.
* **`tofu fmt`** — Автоматически форматирует конфигурационные файлы (`.tf`), выравнивая отступы и приводя код к каноническому стилю HCL.
* **`tofu validate`** — Проверяет синтаксическую корректность кода, внутреннюю логику и типы данных без обращения к провайдерам или реальной инфраструктуре.
* **`tofu plan`** — Выполняет "сухой прогон". Сравнивает текущий код с файлом состояния и показывает план действий (что будет создано, изменено или удалено).
* **`tofu apply`** — Применяет изменения. Создает реальные ресурсы и записывает актуальную информацию о них в файл состояния.

## 🔁 Идемпотентность в OpenTofu
При повторном запуске команды `tofu apply` без изменения кода система вывела: 
`Outputs: 0 added, 0 changed, 0 destroyed`.

**Идемпотентность** — это свойство инструмента возвращать один и тот же результат при многократных вызовах. OpenTofu видит, что ресурсы, описанные в коде, уже существуют в файле состояния и на диске, поэтому он не выполняет никаких лишних действий.

## 🔒 Файл состояния (State) и безопасность
Команды для инспекции состояния:
* `tofu state list` — показывает список управляемых ресурсов.
* `tofu state show random_pet.my_pet` — выводит детальные атрибуты конкретного ресурса.

### Почему State-файл нужно защищать и нельзя коммитить в Git?
1. **Чувствительные данные**: Файл `terraform.tfstate` хранит абсолютно все данные (включая пароли, токены и приватные ключи) в **открытом текстовом виде** (plain text), даже если в коде переменная помечена как `sensitive`.
2. **Конфликты и перезапись**: Если над проектом работают несколько человек, коммиты файла состояния в Git неизбежно приведут к конфликтам слияния (merge conflicts). Если два инженера одновременно запустят изменения, они могут сломать инфраструктуру друг друга. В реальных проектах стейт хранят в удаленных хранилищах (например, S3) с поддержкой блокировок (locking).
